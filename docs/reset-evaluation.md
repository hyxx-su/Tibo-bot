# 초기화 분석 평가

현재 방식은 Gemini 모델을 별도로 학습시키는 fine-tuning이 아니다. 운영과 동일한 `analyzeReset` 함수로 사람이 검토한 사례를 평가하고, 틀린 사례를 근거로 프롬프트와 원문 검증·시간 변환을 보완한다. 게시글이 쌓인다고 모델이 자동으로 학습하거나 기억하지 않는다.

Gemini 3.5 Flash-Lite의 추론 수준은 `MEDIUM`, 출력 상한은 4,096토큰으로 지정한다. [Google 공식 문서](https://ai.google.dev/gemini-api/docs/thinking)에 따르면 이 모델의 기본 수준은 `minimal`이다. 호출 횟수를 늘리는 이중 판정 대신 같은 요청 안에서 대상·부정·완료 범위를 더 검토하도록 설정했다. 기본 설정보다 토큰 사용량·응답 시간이 늘 수 있으며, 모델·추론 설정 변경도 새 평가 대상으로 취급한다.

## 자료와 정답 기준

- 원문·게시 시각·직접 연결된 같은 작성자의 앞선 문맥을 기준으로 한다. 미래 답글을 앞선 게시글의 입력에 넣지 않는다.
- [codex-reset.com 공개 API](https://codex-reset.com/developers)는 누락 사례와 과거 초기화 기록을 찾는 별도 참고 자료로 사용한다. 운영 알림에 해당 사이트의 분류나 예측 확률을 그대로 전달하지 않는다. Data: [codex-reset.com](https://codex-reset.com/).
- 사이트의 `announced_at`에는 운영자가 반영을 관찰한 시각도 포함된다. 이것을 Tibo의 게시 시각이나 원문의 완료 표현으로 대신하지 않는다. 예정 글에 연결된 사이트의 완료 기록도 원문의 상태 정답과 다를 수 있다.
- 완료는 현재 글의 명시적인 완료 근거가 필요하다. 단순 선언·즐기라는 인사만 있으면 보류하고, 일부만 반영되었다는 제한도 보존한다. 명확한 완료 문장에 반드시 `everyone`이라는 단어가 필요한 것은 아니다.
- 사용량 오류 수정·크레딧 보상·한도 상향은 초기화가 명시되지 않으면 일반 글이다. 초기화권 지급은 현재 사용량의 초기화 완료가 아니다.
- `within`은 게시 시각부터 계산한 기한이다. `EOD`, `soon`, 연결 문맥 없는 `Done`처럼 근거가 부족한 입력은 임의의 시각·완료를 만들지 않는다.

사람이 미리 정한 분류와 시각을 정답으로 저장한다. 모델 출력으로 정답을 자동 생성하지 않는다. 해석이 여러 개인 글은 허용 상태 목록으로 별도 집계하며 단일 정답 정확도에서 제외한다. 입력에 문맥이 없는 글의 보류가 맞았다는 결과는 실제 초기화 공지를 모두 찾았다는 뜻이 아니다.

개선용 `dev`와 최종 확인용 `holdout`은 연결된 스레드 단위로 분리한다. `holdout` 결과를 보고 수정하면 그 자료는 이후 개선용으로 취급하며, 다시 실행한 수치를 새로운 독립 평가처럼 설명하지 않는다.

## 비공개 평가 자료

수집 원본·API 키·실제 보고서는 공개 저장소 밖에 둔다. 다음은 형식만 보여주는 합성 예제다.

```json
{
  "version": 1,
  "cases": [
    {
      "name": "synthetic-ordinary-update",
      "split": "dev",
      "post": {
        "id": "100",
        "date": "2026-10-26T00:00:00Z",
        "text": "The editor now supports a new color theme.",
        "context": []
      },
      "expected": { "status": "unrelated", "timestamp": null }
    }
  ]
}
```

`expected.timestamp`는 UTC Unix 밀리초이며 `null`은 변환 가능한 시각이 없어야 한다는 뜻이다. 이 필드를 생략하면 시각 일치 여부를 채점하지 않는다. `expected.relation`은 필요한 경우 `deadline` 또는 `at`으로 지정한다. 모호한 사례는 `expected.status`를 허용 상태 배열로 지정한다. 실제 ID·원문을 이 예제 파일이나 공개 테스트에 추가하지 않는다.

## 실행과 재개

API 키가 `GEMINI_API_KEY`로 저장된 비공개 환경 파일을 사용한다. 운영 DB·Queue·Discord에는 접근하지 않는다.

```sh
node --env-file=/absolute/private/evaluation.env scripts/evaluate-reset-corpus.mjs \
  --dataset /absolute/private/corpus.json \
  --report /absolute/private/report.jsonl \
  --split dev --limit 25 --interval-ms 5000
```

- 기본 호출 상한은 25회다. `--limit`은 한 번 실행할 때 새로 호출할 최대 횟수이며 잔여 API 할당량을 의미하지 않는다. 이 오프라인 평가의 호출은 운영 봇의 일일 분석 카운터와 별개로 같은 Gemini 프로젝트 할당량을 사용한다.
- 429 응답에서는 즉시 중단한다. API 사용량·재시도 가능 시점을 확인한 후 같은 명령으로 재개한다. 결제 전환이나 다른 키로 제한 우회는 하지 않는다.
- 입력·정답·분석 구현이 동일한 정상 응답 결과는 보고서에서 재사용한다. 오분류 결과도 저장하며, API 오류는 재개 시 다시 시도한다. 구현이 바뀌면 새 평가가 필요하다.
- 보고서 권한은 `0600`이다. 사례 이름, 기대·실제 상태와 시각, 통과 여부, 토큰 수, 안전하게 축약한 오류만 기록한다. 원문·모델 요약·키·외부 오류 원문을 기록하지 않는다.
- 최종 확인에는 `--split holdout`을 사용한다. 전체를 실행하려면 `--split`을 생략한다. 종료 코드 `0`은 선택 사례 전부 통과, `1`은 실패, `2`는 호출 상한·429 등으로 일부 미실행이다.
- 출력의 `falseCompleted`는 단일 정답 사례 중 완료 오탐 수다. `confusion`은 상태별 혼동 행렬이며 API 오류도 별도로 표시한다. 모호한 사례와 미실행 사례를 성공률에 섞지 않는다.

기존 합성 프롬프트 평가 도구는 `scripts/evaluate-reset-analysis.mjs`다. 일반 회귀 테스트 `npm test`는 실제 Gemini API를 호출하지 않는다.

## 범위 한계

무료 미러에서 얻을 수 있는 원문은 전체 X 이력이 아니다. 미러의 빈 페이지·누락 문맥·이미지 속 글은 평가 범위를 제한한다. 원문 분류와 수집 누락은 별개로 점검해야 한다. 이번 개선은 프롬프트·시간 해석·오프라인 평가 범위이며 수집 원본 공급원을 바꾸지 않는다. 모델 출력에는 변동성이 있으므로 유한한 사례의 통과가 미래 모든 글의 정확성을 보장하지 않는다.
