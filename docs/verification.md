# 검증 기록

작성일: 2026-10-25, 한국 시간.

## 단일 메시지 형식 변경 검증

초기화 후보는 먼저 분석하고, 초기화 감지 내용과 원문 링크를 한 메시지로 전송하도록 변경했습니다. 일반 글과 무관한 reset 글은 링크만 보냅니다. 분석 최종 실패도 링크 한 건으로 마무리합니다. 분석 일일 상한에 도달한 후보는 다음 날까지 발송을 대기합니다.

- 제목, 월·일·시각, KST·추정 표시, 설명, 원문 링크 형식 확인
- 초기화 글에 링크 단독 메시지가 추가 전송되지 않는 통합 Queue 테스트 통과
- 분석 최종 실패 시 링크 한 건만 전송하는 테스트 통과
- 전체 72개 테스트 통과 후 실제 Worker 배포 완료
- 기존 실제 예시 알림을 새 형식으로 수정하고 Discord API로 본문 일치 확인

아래 기록의 링크와 초기화 공지를 각각 보내는 동작은 이 변경 전 검증 이력입니다. 새 형식으로 자연 발생한 신규 글을 관찰한 결과와 기존 예시 메시지 수정 검증은 구분합니다.

## 자동 알림·스레드 기한 해석 추가 검증

기존 30개 검증 테스트에 자동 알림·시간 변환·스레드 문맥·단건 재검증을 추가해 **71개 테스트가 통과**했습니다. 이후 아래 기능을 실제 무료 Cloudflare 환경에 배포했습니다.

- 1분 Cron의 반복 실행과 연결된 Queue 수집 로그 확인
- 최초 수집에서 기준점만 저장하고 과거 글을 발송하지 않는 동작 확인
- 사용자 지정 실제 스레드 한 건을 관리자 Queue 작업으로 다시 수집
- X 원문 링크만 담은 Discord 메시지 전송 확인
- Gemini가 본문과 시간 답글을 함께 분석해 `scheduled`와 변환 가능한 기한을 반환
- `By midnight PST`를 게시 당시 PST 날짜의 다음 자정으로 계산하고, 한국시간 17:00 **까지**로 표시
- 연결 본문과 시간 답글 링크가 포함된 초기화 예정 메시지를 Discord API로 재조회해 내용 확인
- 자동 발송과 초기화 공지의 처리 단계가 모두 완료되는 로그 확인

실제 한 건의 링크 발송 CPU는 4ms, 분석은 5ms(총 454토큰), 초기화 공지 발송은 2ms였습니다. 수집 실행은 일부 표본에서 10ms를 넘었지만 해당 Queue 실행의 결과는 `ok`였습니다. 이 수치는 소수 실행의 관측치이며 장기 부하나 모든 요청의 성공을 보장하지 않습니다.

이 예시는 감시 시작 전 게시글이므로 관리자 재검증으로 발송했습니다. 자연스럽게 새 글이 올라오는 미래 이벤트를 관찰한 결과로 계산하지 않았습니다. 실제 Discord 클라이언트 화면은 Mac 잠금 때문에 확인하지 못했으며, 봇 인증으로 채널 메시지를 조회해 원문 링크와 변환된 알림을 확인했습니다.

D1 최초 저장 구조는 관리 콘솔로 적용했습니다. 스레드 문맥 열은 사용자가 콘솔에서 적용한 성공 화면을 확인한 뒤 배포했습니다. CLI OAuth 연결에는 D1 관리 권한이 없어 마이그레이션 명령 자체는 성공하지 않았습니다.

현재는 자동 수집이 활성화된 상태입니다. 아래의 빈 Cron 및 검증 프로토타입 설명은 자동 알림을 추가하기 전의 이력입니다.

## 공개 저장소 버전

`npm test`의 배포 없는 빌드와 30개 테스트가 통과했습니다.

- 수집 9개: 작성자 구분, 답글·날짜, 표본 반환, 403·429, 점검 HTML, 필수 필드 누락, HTTPS 설정, 연결 실패
- Discord 21개: 요청 서명과 본문 보존, 잘못된 입력과 실행 대상, 지연 응답, Queue 연결, 같은 원본 메시지 수정, 만료·재시도

테스트의 서명 키, interaction token, API 응답, HTML은 합성 데이터입니다. 실제 API 성공이나 분류 정확도를 이 테스트 개수로 설명하지 않습니다.

공개 예제 설정으로 실제 계정에 배포하지 않았습니다. 개인별 Worker·D1·Queue·Discord 설정이 필요합니다.

## 이관 전 프로토타입의 실제 실행

별도 비공개 검증 환경에서 다음을 확인했습니다.

| 항목 | 결과 |
| --- | --- |
| 실제 무료 Worker에서 저장 HTML 40개 파싱 | CPU 5·5·5·6ms |
| 공개 미러에서 두 페이지 수집·파싱 | 대상 글·답글 40개, CPU 7ms |
| Queue 재시도 | 같은 합성 메시지의 1회차 재시도, 2회차 ack |

| Gemini | 실제 Cloudflare 호출 성공, 한 표본에서 총 200토큰 사용 |

이 수치는 이관 전 코드와 소수 샘플의 결과입니다. 공개 저장소의 새 파일 구성으로 실제 계정에 재배포한 성능 측정이나 전체 부하 검증을 대신하지 않습니다.

무효 응답 토큰으로 수행한 거부 경로 시험을 정상 메시지 전송 성공으로 계산하지 않았습니다.

2026-10-25 오후 1:21(한국 시간)에 대상 서버·채널의 Discord 클라이언트에서 `/검증`을 실행했습니다. 본인만 볼 수 있는 지연 응답 이후 `검증 완료 · Cloudflare에서 실행`이라는 최종 응답을 화면에서 확인했습니다.

## 수집 완전성

미러는 한때 HTTP 429를 반환한 뒤 정상 응답으로 복구됐습니다. 현재 접근 가능하더라도 상시 가용성을 보장할 수 없습니다.

외부 초기화 피드를 저장 표본 20개와 비교했을 때 10개만 포함됐습니다. 해당 피드도 전체 글 수집원의 대체재로 확정하지 않았습니다.

개인 화면, 실제 계정·리소스 ID, 수집 원본, 비밀 설정과 기존 로컬 이력은 이 저장소에 포함하지 않았습니다.


## 미디어 답글 누락 및 링크 미리보기 수정

2026-10-25에 본문이 비어 있는 이미지 답글을 불완전한 게시글로 판단하여 해당 페이지 수집이 중단되는 조건을 확인했습니다. 게시글 ID·날짜와 직접 첨부한 이미지·GIF·동영상이 있으면 본문이 비어 있어도 수집하도록 수정했습니다. 프로필 사진이나 인용 카드의 이미지는 첨부 판정에서 제외합니다.

- `npm test`: 80개 통과. 이미지·GIF·동영상 수집, 비어 있는 첨부 거부, 프로필·인용 이미지 제외, 미디어 답글과 일반 글 동시 발송 및 중복 방지를 확인했습니다.
- 기존 메시지의 `SUPPRESS_EMBEDS` 설정을 해제했으며, 신규 알림도 해당 플래그를 전송하지 않습니다. 일반 링크와 초기화 알림에서 실제 Discord 미리보기를 확인했습니다.
- 수정본을 Cloudflare에 배포한 뒤 운영 수집 경로로 누락된 이미지 답글 한 건을 복구했습니다. 14:45 KST에 전송된 메시지에서 이미지 임베드를 Discord API로 확인했습니다.
- 실제 실행 로그에서 신규 글 한 건 저장, 링크 전송 완료, 이어진 수집의 신규 저장 0건을 확인했습니다. 기준점과 기존 발송 이력은 유지했습니다.

이미지 내용 자체를 AI로 읽는 기능은 포함하지 않습니다. 실제 미리보기 생성과 미러의 갱신 속도·완전성은 외부 서비스 상태에 영향을 받습니다. 실제 운영 검증은 이미지 답글 한 건이며 GIF·동영상은 합성 표본 테스트로 검증했습니다.


## Discord 온라인 표시

2026-10-25에 SQLite 기반 Durable Object 한 개를 추가하여 Discord Gateway에 `online` 상태로 연결했습니다. 기존 Cron이 연결을 복구하고, 게시글 수집과 발송은 기존 Queue 경로를 유지합니다. 채팅 내용이나 사용자 presence를 수신하는 privileged intent는 사용하지 않습니다.

- `npm test`: 92개 통과. 단일 연결, 세션 재개, Heartbeat ACK 누락, 인증 제한, 잘못된 연결 주소 거부, 비활성화, Gateway 장애 분리를 검증했습니다.
- 첫 운영 점검에서 업그레이드용 시간 제한이 연결 후에도 남아 소켓을 끊는 문제를 발견했습니다. 연결 완료 시 타이머를 해제하도록 수정하고 회귀 테스트 후 다시 배포했습니다.
- 실제 Cloudflare 연결에서 READY와 Heartbeat ACK를 확인했습니다.
- Discord 클라이언트 멤버 목록에서 `온라인, 2명` 및 `Tibo-test, 온라인` 표시를 확인했습니다.

장기간 무중단 운영을 보증하는 검증은 아닙니다. 외부 WebSocket은 실행 시간 무료 한도를 소비하며, 다른 Durable Objects 사용량·배포·네트워크 장애에 따라 일시적으로 오프라인이 될 수 있습니다.


## 자격 증명 교체 준비

2026-10-25에 사용자가 새 Gemini 키를 발급한 뒤 키 값을 로그·Git에 남기지 않고 비공개 파일과 Cloudflare secret으로 등록했습니다. 최소 API 호출 HTTP 200과 실제 Discord `/검증`의 수집·Gemini 분석·D1·Queue·최종 비공개 응답 성공을 확인했습니다. 반복 실행에 대한 호출 제한 안내도 실제 화면에서 확인했습니다. 후속 단계에서 사용자가 기존 Gemini 키 삭제와 Discord 토큰 초기화를 완료했습니다. 기존 Gemini 키가 목록에서 사라지고 새 키만 남은 것을 확인했습니다. 새 Discord 토큰의 앱 인증 HTTP 200과 이전 토큰 HTTP 401을 확인한 뒤 Cloudflare secret과 비공개 로컬 값을 교체했습니다.

Discord 토큰 초기화 후 이전 토큰의 인증 실패 대기가 새 토큰에 남지 않도록 Gateway에서 SHA-256 해시로 토큰 교체를 구분합니다. 같은 토큰으로 재배포하면 기존 대기를 유지하고, 토큰이 달라져도 최소 인증 간격은 유지합니다. 해당 회귀 검증을 포함해 `npm test` 119개가 통과했으며 실제 Worker에 배포했습니다.


## 인증정보 교체 완료 검증

운영에 사용하는 Gemini API 키와 Discord 봇 토큰을 모두 교체했습니다. 키·토큰 값은 대화·공개 파일·Git 이력에 기록하지 않았습니다. 새 값의 비공개 로컬 파일 권한은 0600입니다.

- 기존 Gemini 키 삭제 후 실제 Discord `/검증`에서 Cloudflare 수집·Gemini 분석·D1·Queue·최종 응답이 성공했습니다.
- 새 Discord 토큰으로 인증한 앱 ID가 대상 앱과 일치했습니다. 이전 토큰은 HTTP 401로 거부됐습니다.
- 새 토큰으로 테스트 메시지를 전송하고 실제 Discord 채널에서 도착을 확인했습니다.
- 최종 `/상태`는 Discord 연결 온라인, 최근 수집 정상, 대기 0건·실패 0건이었습니다.
- 새 토큰을 표시한 개발자 포털은 다시 불러와 토큰 값을 화면에서 숨겼습니다. 토큰 교체 중 기존 발송 이력을 초기화하거나 과거 글을 재발송하지 않았습니다.
