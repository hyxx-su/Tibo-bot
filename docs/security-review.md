# 보안 점검 기록

점검일: 2026-10-25. 공개 저장소 코드·Git 이력, 배포 설정의 구조, 로컬 자격 증명 파일 권한, 의존성, GitHub 보안 설정과 실제 Worker 응답을 확인했습니다. 침투 테스트나 무결점 보증을 대신하지 않습니다.

## 개선 사항

| 항목 | 확인한 위험 | 적용한 조치 |
| --- | --- | --- |
| 요청 재사용 | 올바른 서명이어도 오래된 요청을 다시 실행할 수 있었음 | 서명 timestamp ±5분 검사, 검증 interaction ID 중복 방지 |
| 검증 API 남용 | 지정 채널의 일반 멤버도 분석을 반복 호출할 수 있었음 | 서버 관리·관리자 권한 검사, 기본 명령 권한 설정, 전체 합계 분당 1회·UTC 하루 20회 제한 |
| 제한 상태 유실 | 메모리만으로 제한하면 재시작·동시 요청에서 우회 가능 | 별도 SQLite Durable Object에서 원자적으로 승인·저장, 저장소 오류 시 승인하지 않음 |
| 공개 상태 조회 | 인증 없는 조회마다 온라인 연결 객체 호출 | 공개 health를 최소 응답으로 변경, 내부 연결 조회는 Discord 비공개 `/상태`로 이동 |
| 외부 데이터 크기 | 본문 전체를 읽은 뒤 크기를 검사하거나 제한하지 않았음 | Content-Length 사전 검사와 실제 스트림 바이트 검사, Discord 64 KiB·미러 2 MiB·Gemini 64 KiB 제한 |
| 외부 목적지 | 설정 오류와 자동 리다이렉트로 예상 밖 주소에 접근할 수 있었음 | 미러 호스트·인증 포함 URL 제한, Gateway 주소 범위 축소, 리다이렉트 자동 추적 중단 |
| 알림 출력 | AI 요약의 Markdown 링크가 공식 안내처럼 표시될 수 있었음 | AI 요약 외부 URL 제거·서식 이스케이프, 기존 멘션 차단 유지 |
| 개발 의존성 | npm audit에서 high 3건·moderate 1건 보고 | sharp 0.35.5, undici 7.30.1 패치 고정 |

호출 제한 저장소는 비밀 토큰 없이 interaction ID와 짧은 만료 시각·카운터만 저장합니다. 일일 상한은 자동 게시글 분석의 기존 상한과 별개입니다. 소량의 저장소 입출력이 발생하지만 Gateway처럼 상시 연결되지는 않습니다. 기존 D1 스키마·발송 이력을 변경하지 않았습니다.

외부 서버 응답은 `redirect: 'manual'`로 받고 HTTP 오류와 리다이렉트를 성공으로 처리하지 않습니다. Workers가 지원하는 동작으로 로컬 통합 테스트를 수행했습니다.

## 검증 결과

- `npm test`: 117개 통과. 실제 Ed25519 서명, 시간 범위, 권한, 요청 중복, 호출량 상한, 동시 승인, 저장소 실패, 입력 크기, 잘못된 수집 주소·리다이렉트, Markdown 링크와 기존 알림 동작을 포함합니다.
- `npm audit`: 초기 4건 → 패치 후 0건. 이는 해당 시점의 npm 취약점 데이터베이스 결과입니다. 패치된 패키지는 개발 도구 의존성입니다.
- 공개 Git 이력의 모든 blob에 대해 지원하는 OpenAI·Google·Discord·GitHub 토큰 패턴을 검사했으며 검출되지 않았습니다. 패턴 검사는 모든 종류의 비밀정보를 탐지하지 못합니다.
- 코드 반영 후 GitHub Dependabot API를 재조회하여 열린 경고 0건, 수정 처리된 경고 20건(sharp·undici)을 확인했습니다. push 직후의 이전 경고 배너와 현재 API 결과를 구분했습니다.
- GitHub secret scanning 경고 0건, secret scanning과 push protection 활성 상태를 확인했습니다. Dependabot 취약점 알림·보안 업데이트도 활성화했습니다.
- 실제 봇 토큰·Cloudflare 로그인 파일은 0600, 상위 비공개 설정 폴더는 0700 권한을 확인했습니다. 내용은 보고서와 Git에 넣지 않았습니다.
- 실제 Worker에 배포했습니다. 공개 health는 HTTP 200으로 최소 정보만 반환하고, 잘못된 메서드는 405, 서명 없는 요청·오래된 요청은 401로 거부하는 것을 확인했습니다.
- Discord API에서 `/검증`의 `default_member_permissions`가 서버 관리 권한으로 설정된 것을 재확인했습니다.
- 실제 미러 페이지를 변경된 수집기로 해석하여 대상 게시글 20개와 이미지 첨부 글을 확인했습니다. 배포 후 자동 수집 로그도 정상 실행 결과를 확인했습니다.
- 이번 배포본의 실제 Discord 명령 화면 재실행은 앱 제어 중단과 Work의 로컬 브라우저 비활성화로 완료하지 못했습니다. 정상 명령·중복·상한 경로는 Miniflare 통합 테스트로 검증했습니다.

## 남은 위험과 운영 조치

1. **대화나 로그에 이미 노출된 API 키·봇 토큰은 발급처에서 폐기·재발급해야 합니다.** 이번 작업에서 자격 증명을 교체하거나 기존 키의 폐기를 확인하지는 않았습니다. 새 값은 채팅·Git에 넣지 말고 비공개 파일과 Cloudflare secret으로 등록해야 합니다.
2. 공개 미러의 위변조·누락과 AI의 오분류 가능성은 남습니다. 원문 링크와 시간 표현 근거를 제공하지만 X 공식 API나 이미지 내용 검증을 추가한 것은 아닙니다.
3. 입력 제한을 넘는 큰 글·응답은 오류로 거부합니다. 수집원 구조·호스트 변경 시 별도 검토가 필요합니다.
4. 애플리케이션의 검증 호출 제한이 대규모 네트워크 공격 방어를 대신하지는 않습니다. Cloudflare 계정 전체의 무료 한도·접근 권한과 발급처 키 사용량을 함께 관리해야 합니다.
5. 패치된 간접 의존성의 버전 고정은 이후 업그레이드 시 재검토해야 합니다. 새 보안 경고가 나오면 테스트 후 패치를 갱신합니다.
