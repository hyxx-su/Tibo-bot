# 제목·요약 의미 보존 개선과 성능 검증

## 범위와 기존 흐름

기준 코드는 `c9b0784`다. 이 보고서는 기존의 초기화 상태/시각 평가와 제목·요약의 사실 일치 평가를 구분한다. 과거 24/24는 전체 요약의 의미 정확도가 아니었다.

자동 알림은 매분 예약 → `watcher.poll` → `collector.collectTimelinePage` → `recordPage`의 게시글 ID 중복 검사 → Queue의 `link/analyze/reset` 단계 → `analyzeReset` → 서버별 전달 작업 → Discord 순서다. `reset`과 일반 `link` 단계의 X 출력 형식은 같다. 사이트 완료 임베드는 별도 검증/전달 흐름이다.

- 수집은 같은 스레드의 앞선 글 최대 5개와 직접/부모 인용을 수집하고, 인용 보충까지 문맥을 제한한다. 단순히 인접한 글을 연결하지 않는다.
- 문맥에 ID·작성자·게시 시각·관계·인용 주체를 전달한다. 타인의 문맥은 요약용이며 초기화 실행 근거로 허용하지 않는다.
- 기존 자동 알림도 제목·요약·초기화 판별을 한 번의 Gemini 요청으로 받았다. `src/gemini.js`의 별도 진단 호출과 자동 알림 경로를 혼동하지 않는다.
- D1 분석 결과 재사용, 게시글 claim, 서버별 전달 이력이 이미 있다. 추가 캐시나 동시성 구조를 도입하지 않았다.
- 수집 타임아웃 20초, 기본 분석 45초. HTTP 503 등 일시 오류는 기존 최대 6회, 검증 실패는 최대 2회 정책을 유지한다. 실패 시 링크를 보내고 성공하면 같은 메시지를 PATCH하는 기존 복구 흐름을 유지한다.
- Queue 단계와 1분 수집 주기, 미러 갱신 지연은 별도 지연 요소다. 아래 API 측정에 이 시간을 포함하지 않았다.

## 확인한 문제와 변경

1. 긴 지침이 주체·행동 보존을 요구하더라도 근거 문자열이 존재하는지만 확인하면 잘못된 한국어 주장을 통과시켰다. 편집 규칙을 정리하고 발언 주체·부정·불확실성·제품명을 구체적으로 구분했다. 초기화 판별 규칙까지 압축한 실험은 회귀가 나타나 폐기했으며, 기존 상세 분류 규칙과 예시를 복원했다.
2. 원문에서 약속하지 않은 사용 의사, 답글 대상의 입사 사실, 냉소적 의도를 만들어내는 사례가 있었다. 비어 있는 제목, 제외 조건 상실, 가능성의 확정화, 제품명 오역, 구호의 의사 확대를 규칙으로 탐지한다. 타인의 1인칭 경력 발표에 대한 짧은 답글 중, 생성 결과가 입사·이직 같은 행동을 주장하는 필드만 주체 재검토 대상으로 삼는다. 단순 축하 인사만 있으면 추가 호출하지 않는다.
3. 뜻이 명확한 완결 표현(forever 구호, Might be, Sounds like bliss)은 오류 필드만 직접 번역해 교정한다. 정상적인 문맥 설명은 유지한다. 그 외 문제가 있는 제목/요약 항목만 추가 호출에 전달한다. 정상 필드와 초기화 분류는 부분 검토가 수정할 수 없다. 수정 필드·길이·근거·잔존 규칙 오류를 다시 검사하고, 실패 결과는 발송하지 않는다. 이 검토는 모든 의미 오류를 보증하는 완전한 판정기가 아니다.
4. 일부 플랜 완료와 나머지 미확인이 함께 있으면 전체 완료를 `mentioned`로 낮추고 그 제한을 제목·요약에 보존하도록 검토한다. 분류와 요약을 통째로 다시 만드는 대신 해당 상태와 편집 필드만 수정한다.
5. 문맥의 고유 내용은 자르지 않는다. 빈 문맥/피드백 필드, 수집용 부가 필드, 동일한 문맥만 제거한다. 다른 작성자·관계·본문의 자료는 보존한다.
6. 중복 요약 제거 후에도 근거 배열이 같은 항목을 가리키도록 함께 정렬한다.
7. 출력 순서는 제목·요약을 분류보다 앞에 두었다. 긴 기능 발표의 마지막 리셋 언급만 제목/요약으로 고르는 편향을 줄이기 위한 조치다. 짧은 반응 대신 과거 문맥의 질문을 요약한 결과도 검토 대상으로 삼는다.
8. 추가 의미 검토도 운영 일일 분석 예산을 예약한다. 성공뿐 아니라 재시도/최종 실패에도 실제 호출 시도 수와 소요 시간을 로그에 남겨 게시글별 호출량을 합산할 수 있게 했다. 검토는 최대 한 번, 자체 타임아웃은 최대 20초이되 기본 분석과 총 45초의 HTTP 처리 예산을 공유한다. 기본 분석이 44초를 넘으면 추가 호출·예산 예약을 시작하지 않는다. 추가 오류는 기존 작업 재시도로 넘긴다. 정상 글의 기본 호출 수는 한 번이다. 기본 분석과 부분 검토는 MEDIUM을 유지한다. LOW/MINIMAL 전면 적용은 분류 회귀로 채택하지 않았다. 본문과 직접 문맥에 관련 단서가 없을 때만 긴 초기화 사례집을 제외하며, 모든 상태 정의·판단 기준·근거 검증은 계속 전달한다. 검증 오류 재시도에는 사례집을 다시 포함한다. HTTP 503만으로 추가 검토 호출을 만들지 않는다.

## 비교 방법

실제 원문 5건과 합성 사례 11건을 사용했다. 실제 원문·문맥·생성 응답·API 키는 비공개 경로에 보관하며 저장소에 포함하지 않는다. 공개 회귀 자료는 `test/fixtures/summary-semantics-cases.mjs`의 합성 사례다.

- 기존 지침, 압축 통합안, 제목/요약과 초기화 분류를 독립 요청으로 나눠 병렬 실행한 분리안을 같은 입력으로 비교했다.
- 이어 의미 오류를 보완한 통합안에서 MEDIUM/LOW 추론 설정을 비교했다. LOW에서 취소 공지 누락이 발생해 채택하지 않았다. 이후 기존 초기화 판별 지침을 복원한 통합안을 별도로 검증했다.
- 분리안은 두 요청이 끝나는 전체 벽시계 시간을 측정했다. P50/P95는 nearest-rank 방식이며 8건 표본의 P95는 최댓값이다. 사용량은 두 요청과 조건부 검토를 합산했다.
- 지연 측정은 같은 로컬 Node 실행 환경에서 Gemini API 응답과 코드 검증이 끝날 때까지의 벽시계 시간이다. 운영 Cloudflare→Discord 종단 지연과 구분한다.
- 오류도 제외하지 않고 기록한다. API 호출 간 7초 대기는 사례 지연에서 제외한다. 실패 시의 운영 Queue 재시도 대기는 이 단건 비교에 포함하지 않는다.
- 정보가 많은 합성 글 한 건은 '이번 출시에는 리셋이 포함되지 않음'이라는 출시 범위 설명의 분류 정답이 모호해 초기화 정확도 분모에서 제외한다. 이 글의 제목·요약 평가는 유지한다. 따라서 초기화 분류 분모와 편집 평가 분모는 다르다.
- 제목은 핵심 대상/행동·조건·확실성을, 요약은 모든 항목의 원문 일치와 주체 구분을 대조한다. 소극적인 가능성을 동의로 바꾸거나, 일정 미발표를 계획 부재로 바꾸면 실패로 판정한다. 단순한 핵심 정보 생략은 사실 일치와 별도로 정보량 한계로 기록한다. 개발 과정에서 사용한 소규모 회귀 표본이며 독립 평가자나 무작위 운영 표본의 정확도가 아니다.

## 폐기한 실험과 추가 보완

- 전체 상세 지침 + MEDIUM의 8건 후보 비교에서는 입력이 줄어도 추론 토큰 증가로 추정 비용이 $0.009964 → $0.016419로 증가했고, 평균도 3.951초 → 4.314초였다. 이 후보를 비용·속도 개선으로 보고하지 않았다. 이후 단서에 따른 사례집 선택과 근거 복원, 출력 순서를 보완했다.
- MINIMAL 전면 적용은 저장형 활성화/반영 대기 상태를 scheduled로 잘못 판단하는 사례가 재현되어 폐기했다. LOW도 같은 분류 회귀와 검토 실패가 발생했다.
- 초기화 지침까지 압축한 통합안과 분리안의 16건 비교에서 평균은 각각 5.895초/8.353초, P50은 3.241초/4.304초, 요청 시도는 18회/34회였다. 분리안은 채택하지 않았다. 이 단계는 최종 배포 성능이 아니다.
- 별도 16건에서 LOW/MEDIUM 평균은 12.035초/13.108초였으나 LOW는 취소 공지를 무관한 글로 놓쳤다. 출력·추론 토큰 합계도 LOW 14,443개, MEDIUM 10,311개로, 낮은 추론 설정이 더 저렴하다는 가정도 성립하지 않았다.
- 압축 통합안의 확장 회귀에서 과거 회상, 모호한 리셋 선언/후속 기한, `in 3 hours`의 접두사 누락이 발견됐다. 핵심 분류 규칙을 복원했다. 초기의 약 64% 입력 토큰 절감 수치를 최종 개선 효과로 사용하지 않는다.
- 명시적인 사용량 초기화 질문을 올바르게 `mentioned`로 분류하고도 근거 필드를 비우는 경우에는, 좁은 질문 형식에서만 현재 원문을 근거로 보완한다. 기기 초기화 같은 다른 대상에는 적용하지 않는다.
- 추가 검토에서 64.852초까지 늘어난 실패가 관찰되어 전체 45초 HTTP 처리 예산을 추가했다. 이는 설정과 시간 제어 테스트로 검증한 제한이며, 과거 측정치를 45초로 잘라 새 실측치로 표시하지 않는다.
- 타인의 주장 출처만 묻는 짧은 답글은 초기화 공지로 승격하지 않도록 제한된 규칙을 적용했다. 자신의 문맥이나 초기화를 직접 언급한 질문에는 이 규칙을 적용하지 않는다. `in N hours`를 `N시간 내`로 바꾼 제목/요약 필드는 선택적으로 재검토한다. 문맥 없는 세 가지 명확한 관용 표현은 검증된 직접 번역 제목을 사용한다. 저장형 지급의 `2/3` 같은 표기는 총수량·단계·계정 비율로 확대하지 않는다.
- 같은 원문 안에서 생략 인용의 각 구절이 순서대로 확인될 때만 연속된 원문 구절로 복원한다. 원문에 없는 구절, 역순, 다른 작성자·게시글 사이의 합성은 계속 거부한다. 최초 요약과 재검토 모두 서로 다른 작성자의 사실을 함께 설명할 때 근거 배열을 받아 각 출처를 따로 검증한다. 기존 문자열 근거 형식은 유지하고 추가 근거를 분석 JSON의 선택적 검토 기록에 보존한다. `배제`처럼 올바른 제외 표현도 인정해 불필요한 재검토와 재시도를 막았다.
- 실제 사용 의사나 출시 계획 부재가 원문에 있을 때 검토 규칙이 이를 과장으로 오인하지 않도록 역방향 테스트도 추가했다.

## 503과 실패 처리

이번 실호출에서도 HTTP 503과 45초 시간 초과가 발생했다. 503은 Google이 응답한 서버 오류이며, [공식 오류 문서](https://ai.google.dev/gemini-api/docs/generate-content/api-errors?hl=en)는 일시적 과부하·가용 용량 부족을 원인으로 설명한다. 이 측정만으로 Google 내부의 정확한 장애 지점까지 확정할 수는 없다. D1 조회 실패나 JSON 검증 실패와 구분해서 기록했다.

기존의 지수형 대기와 `Retry-After`, 인증 오류의 영구 실패 처리, 실패 시 원문 링크 전달 및 추후 같은 메시지 수정 흐름은 유지했다. 모든 실패 직후 모델 호출을 더 추가하거나, 검증하지 않은 모델로 바꾸지 않았다. 이번 변경은 제공자 503 자체를 제거한 것이 아니라, 불필요한 요청과 추가 검토의 대기 시간을 제한하고 의미 검증 실패를 안전하게 처리한 것이다.

## 검증 이력

- 로컬 `npm test`: Wrangler 빌드와 **794개 테스트 통과**, 실패 0개. 저장·전달·시간 변환·일반 채팅 등 기존 회귀도 포함한다.
- 확장 실호출은 복구 사례 3개 + 기존 회귀 35개 + 별도 평가 12개, 총 50개였다. 첫 확장 실행에서 자동 상태/유형/시각/관용어 검사 44/50개가 통과했다. 3개는 응답 미확보, 3개는 분류 불일치였다. 이 실행에서는 503 4회, 시간 초과 2회, 현재 글 근거 검증 실패 1회가 관찰됐다.
- 이 자동 검사는 제목·요약 전체 의미 정확도가 아니다. 별도 원문 대조에서 자신으로 잘못 지칭한 밈 번역과 상대 시각의 기한화도 발견했다.
- 영향 사례 10개를 재호출해 8개가 통과했고, 남은 감사 인사의 과거 완료 복사와 명사형 초기화 언급은 추가 보완 후 2/2개 통과했다. 감사 인사는 추가 호출 없이 직접 의미를 보존하며, 명사형 언급의 근거 누락은 원문 전체로 보완하고 잘못된 실행 상태 문장만 재검토한다.
- 각 단계는 코드가 달라진 반복 개선 기록이다. 이를 최종 버전의 단일 50/50 실행이나 운영 정확도 100%로 보고하지 않는다. 보완에 사용한 별도 출처 질문 사례는 회귀 자료로 이동했다.
- 최종 비교용 8개 입력은 실제 사례 5개와 합성 사례 3개로 사전에 선택했다. 기존/개선 실행 순서를 번갈아 배치하고 다른 AI 검증을 동시에 실행하지 않았다. 마지막 실행은 4쌍을 마친 뒤 다섯 번째 기존 버전 요청에서 HTTP 429가 발생해 중단했다. 아래에서는 완료한 4쌍과 실패한 단독 요청을 구분한다.

최종 확장 실행은 50건 중 첫 시도 40건, 최대 2회 시도 후 45건이 통과했다. 반환된 결과의 상태·유형·시각 불일치는 없었고, 5건은 결과를 반환하지 못했다. 실행 중 HTTP 503 8회와 근거 필드 검증 오류 7회가 기록됐다. 질문·취소·부정·회상에서 evidence는 실행 증거가 아니라 그 언급 문장 자체임을 지침에 명시했다. 미반환 5건과 지급 분수/취소 2건을 별도로 재검증해 **7/7건 모두 한 번의 호출로 통과**했다. 이 기록은 일괄 첫 시도 성공률 100%를 의미하지 않는다.

## 최종 측정 결과와 판정

**의미 보존 개선은 확인했으나, 정확도·속도·비용을 동시에 개선한다는 목표는 아직 충족하지 못했다.** 입력 축소를 전체 비용 감소로 표현하지 않는다. 분리 호출과 LOW/MINIMAL 전면 적용은 채택하지 않았으며, 기존 통합 호출에 제한적인 의미 교정만 추가했다.

마지막 코드의 동일 입력 4쌍 비교다. 추가 검토의 사용량도 합산했다. 모두 짧은 일반 글/답글이므로 운영 전체 분포를 대표하지 않는다.

제목 평가에서 기존의 영어 구호 그대로인 제목과 “댓글에 대한 짧은 반응 게시”는 말뜻 전달 실패로 처리했다. 요약 사실 일치에서는 원문에 없는 냉소적 태도 단정을 실패로 처리했다. 구호를 “초기화와 무관한 글”로 대신 설명한 결과는 사실 일치와 별개로 의미 전달 실패다. 축하 대상과 입사 발표자를 구분한 개선 결과는 각 원문의 작성자와 대조했다. 한 평가자의 개발 사례 대조이며 통계적으로 입증된 운영 정확도 상승률은 아니다.

다섯 번째 기존 요청은 **0.931초 후 429**로 실패했고, 짝이 되는 개선 요청은 보내지 않았다. 최종 실행 전체는 기존 5건 중 1건 실패, 개선 4건 중 실패 0건이지만, 표본 수와 순서가 달라 실패율 개선으로 비교할 수 없다. 실패 요청의 사용량은 미보고 상태다. 429의 세부 제한 종류(RPM/일일/프로젝트 한도)는 이 기록만으로 확정할 수 없어 추가 호출을 중단했으며, 해소됐다고 주장하지 않는다. 위 표에서 제외한 이유는 같은 입력의 쌍 비교를 유지하기 위해서이며, 오류를 성공처럼 처리하지 않았다.

직접 번역 교정을 추가하기 직전에는 동일 8건 모두 비교를 완료했다. 기존/후보 평균은 **3.614/5.584초**, P50 **3.478/6.022초**, P95 **5.452/8.061초**, 호출 수 **8/12회**, 입력 **4,803.88/3,374.38토큰·게시글**, 추정 비용 **$0.001458/$0.002209·게시글**이었다. 그 결과 불필요한 짧은 표현 재검토를 코드 교정으로 줄였다. 이 8건 수치를 마지막 코드의 측정치로 대체하지 않는다. 당시 저장형 활성화 글은 상태가 in_progress로 맞았지만 제목은 “제공 예정”이라고 표현해 현재 활성화와 반영 대기를 충분히 구분하지 못했다. 상태 정확도만으로 제목 품질을 보증할 수 없는 잔여 사례다.

이후 예상치는 실측과 구분한다. 추가 검토를 안전하게 생략할 수 있는 글은 **최대 1회 요청과 그 요청의 실제 토큰**을 절약할 수 있다. 그러나 운영의 검토 비율·지연 분포가 없어 전체 평균/P95·월 비용 절감률은 산출하지 않는다. 현재 4건의 수치를 대규모 운영 예측으로 외삽하지 않는다.

## 비용과 재현

`node scripts/benchmark-summary.mjs --output=/비공개경로/report.jsonl`로 합성 자료를 실제 호출할 수 있다. `--module`은 비교할 분석 모듈, `--dataset`은 비공개 `{name,status,post}` 배열, `--split`은 현재 지침의 분리 호출 실험이다. 환경변수 `GEMINI_API_KEY`가 필요하다. 원문과 응답은 권한 0600의 지정 파일에만 저장하며 콘솔에는 지연·호출 수·오류 코드만 기록한다.

추정 비용은 Gemini 3.1 Flash-Lite Standard의 입력 $0.25/100만 토큰, 캐시 입력 $0.025/100만, 출력(추론 포함) $1.50/100만으로 계산한다. 실제 청구액이 아니며 무료 구간 여부는 반영하지 않는다. 사용량이 반환되지 않은 실패 요청의 토큰/비용은 알 수 없다. [Google 가격표](https://aistudio.google.com/docs/pricing#gemini-3.1-flash-lite)

## 제한과 후속 우선순위

1. 429 제한이 해제된 후 마지막 코드의 8건 비교를 완주하고, 개발에 사용하지 않은 운영 표본으로 반복 측정한다. 추가 호출은 실행 목적과 예산을 정한 뒤 진행한다.
2. 주체 검토의 오탐과 불필요한 추론을 먼저 줄인다. 이미 정확한 문장을 재검토하는 비용이 관찰됐지만, 이를 일괄 제거하면 주체 혼동 방어도 사라지므로 별도 평가가 필요하다.
3. 초기화 상태와 제목의 시제 일치를 확대 검증한다. 활성화와 전체 계정 반영 대기는 서로 다른 사실이며, 향후 기한처럼 보이는 제목의 범위를 점검한다.
4. 운영 Queue/수집/Discord 구간 지연을 추가된 로그와 기존 전달 로그로 분리 집계한다. 현재 API 실측을 종단 지연으로 사용하지 않는다.

- 프롬프트나 구조화 JSON만으로 사실 일치를 보장할 수 없다. 조건부 의미 검토도 모델 판단이므로 새로운 형태의 주체 혼동은 남을 수 있다.
- 재검토 자체가 실패하면 기존 Queue 재시도에서 기본 분석도 다시 실행한다. 검토 초안을 별도 저장해 재개하는 방법은 DB/저장 흐름 변경이 필요하므로 이번 범위에서 도입하지 않았다.
- 다음 우선순위는 실제 새 글의 지연·오류·추가 검토 비율을 관측하고, 개발에 쓰지 않은 사례로 제목/요약 정확도를 재평가하는 것이다.
- 명시적 프롬프트 캐시, 더 많은 병렬 처리, Queue 단계 합치기는 실제 운영 병목과 비용 효과를 측정한 뒤 판단한다. 저장 비용·호출량·중복 발송 위험을 검토하지 않고 추가하지 않는다.
